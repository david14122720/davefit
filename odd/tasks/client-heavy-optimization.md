**Objective**: Descargar cómputo al cliente; servidor dedicado a servir estáticos livianos + JSONs pequeños. Servidor objetivo: 1 núcleo, 2GB RAM, 100 Mbps. Clientes: móviles modestos con red baja.

## Decisiones registradas (Log)

- **Ruta crítica identificada (S6)**: `/biblioteca`. Justificación: es el destino del redirect de `/` y del catch-all (`*`) en `App.tsx` (L117, L123), es la página hub pública que todo usuario visita (anónimo y logueado), y hace 2 fetchs en paralelo del catálogo completo. La landing `index.astro` ya es SSR liviana con ClientRouter.
- **NO se agrega Service Worker (S5)**: `BaseLayout.astro` contiene un script "SW killer" deliberado (remediación de pantalla negra, CSP hash fijado, ver comentario L90-122) que desregistra TODOS los service workers y borra TODOS los caches en cada carga. Conflictuaría con ese fix. La caché moderada se implementa vía HTTP headers (equilibrada: inmutable 1y para assets hasheados `/_astro/` que底盘 ya existen; TTL corto/moderado para el resto; HTML siempre revalidado). La caché por headers es gestionada por el navegador (disco), no acumula storage JS → cumple la restricción de RAM de S5.
- **Brotli descartado**: el `nginx` de Alpine no incluye módulo brotli y no podemos rebuilt del servidor. Se mantiene gzip (ya activo) + precompresión con `gzip_static`.
- **Servir estático directo desde nginx**: `dist/client` está copiado en el contenedor (`Dockerfile` L27). nginx pasa a servir `/_astro/*` y assets públicos desde disco (root directo), liberando al proceso Node SSR de 1 núcleo. Cumple la filosofía de S4 de "servir archivos estáticos livianos".
